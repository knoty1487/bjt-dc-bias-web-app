# Reflection — Lab 02

## สิ่งที่ได้เรียนรู้

การสร้าง Web App ครั้งนี้ทำให้เห็นชัดว่าไฟล์ HTML เพียงอย่างเดียวไม่ใช่
"โปรแกรม" ทั้งหมด — เมื่อเปิด `templates/index.html` ตรง ๆ ด้วย `file://`
ฟอร์มจะไม่มี Python รันอยู่เบื้องหลัง และไม่มีการคำนวณใด ๆ เกิดขึ้น
การทำงานจริงต้องมี Flask Server คอยรับ HTTP Request จาก Browser

ฟอร์มส่งข้อมูลไปยัง Python ผ่าน `POST /calculate` เป็นคู่ `name=value`
ของแต่ละช่อง (รวมหน่วย Ω/kΩ) จากนั้น `app.py` อ่านค่า ตรวจสอบ แปลงหน่วย
เรียก `dc_bias.py` และส่งผลลัพธ์กลับไปแสดงผ่าน Jinja Template

การแยก `dc_bias.py` ออกจาก `app.py` มีประโยชน์มาก: เมื่อต้องแก้สมการ
เช่น เปลี่ยนวิธีประมาณ IB หรือเพิ่มการเตือน เราแก้ที่ไฟล์เดียวโดยไม่ต้อง
แตะ HTML เลย และสามารถทดสอบสมการด้วย unittest โดยไม่ต้องเปิดเว็บ

## เรื่องที่ต้องระวัง

- หน่วยต้องสอดคล้อง: ตัวต้านทานกรอกเป็น kΩ ได้ แต่ต้องแปลงเป็น Ω
  ก่อนเข้าสมการ ไม่งั้นผลจะผิดหลักพันเท่า
- แบบจำลอง Forward-Active ใช้ได้เฉพาะบางช่วงการทำงาน เมื่อ `VTH ≤ VBE`
  ทรานซิสเตอร์ Cutoff และเมื่อ `VCE` ต่ำใกล้ Saturation สมการ IB = βIC
  แบบคงที่ใช้ไม่ได้จริง จึงต้องแสดง Warning ไม่ใช่ปล่อยให้ผู้ใช้เข้าใจว่า
  เป็นผลที่แม่นยำ
- การทดสอบช่วยจับข้อผิดพลาดได้จริง เช่น ตอนแรกต้องตรวจว่าผลที่แสดง
  มาจาก Backend ไม่ใช่ค่าที่ hard-code ไว้
